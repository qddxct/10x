# P6 · 回测与复盘 实施计划

**日期**：2026-04-21
**范围**：历史回测引擎、BacktestSession 持久化、API、前端 `/backtest` 表单 + 图表 + 双模型对比

## 决策记录

- **Q1（赔率来源）**：C — MVP 先使用当前 `MatchOdds` 唯一记录，`match_odds_history` 快照表延后到 P7+
- **Q2（执行方式）**：C — 同步执行 + 写入 `BacktestSession` 保留历史（便于 `GET /backtest/{id}` 回读）
- **Q3（盈亏口径）**：C — 同时输出
  - 固定单位：每次 1 单位，命中 = `odds - 1`，未命中 = `-1`
  - Kelly：按 `kelly_pct` 从初始本金滚动下注，命中 = `bet * odds - bet`，未命中 = `-bet`
- **Q4（前端）**：C — 基础卡片（命中率 / ROI / 盈亏）+ Recharts 折线图（累计盈亏）+ 饼图（分数段分布）+ 双模型并排对比

## 任务

### T1 · BacktestSession schema 理清
- 现有表已覆盖主要字段（date_from/to、total_bets、hit_count、hit_rate、roi、profit_loss、results_by_*）
- 新增字段（通过 alembic `0004`）：
  - `mode` ENUM('fixed','kelly')：单次回测的资金模型（默认 fixed）
  - `initial_capital` DECIMAL(14,2) nullable：Kelly 模式本金
  - `kelly_profit_loss`, `kelly_roi` DECIMAL：Kelly 模式独立盈亏
- 测试：ORM round-trip 验证新字段默认值 + 可空

### T2 · engine/backtest.py 纯函数
- `BetOutcome`：dataclass `(score_id, bet_type, odds, kelly_pct, stake_fixed, pnl_fixed, stake_kelly, pnl_kelly, is_hit)`
- `decide_outcome(bet_type, asian_handicap, result, handicap_result) -> bool`：判定命中
  - `draw` + `result=="draw"` → True
  - `handicap_draw` + `handicap_result=="draw"` → True
- `simulate_bet(odds, kelly_pct, current_capital, is_hit) -> (pnl_fixed, pnl_kelly, stake_kelly)`：计算单场两种口径盈亏
- `aggregate(outcomes) -> BacktestStats`：
  - `total_bets`, `hit_count`, `hit_rate`
  - `roi_fixed`, `profit_loss_fixed`
  - `roi_kelly`, `profit_loss_kelly`
  - `by_score_band`：{ "78-84": {bets, hits, roi}, ... }
  - `by_league`：{ "英超": {...}, ... }
  - `equity_curve`：[ {date, cumulative_pnl_fixed, cumulative_pnl_kelly}, ... ]
- 全部 TDD，覆盖命中/未命中/让平/多联赛/空结果

### T3 · engine/backtest_service.py
- `BacktestService(db).run(config_id, date_from, date_to, *, mode, initial_capital) -> BacktestSession`
  - 查询区间内所有已完赛比赛（`match_results` 存在）
  - 对每场调用 `ScoringService.compute_for_match` 获取 `MatchScore`
  - 只保留 `is_recommended=True` 的比赛
  - 通过引擎模拟下注 → 聚合 → upsert 写入 `BacktestSession`
- 测试：2 场比赛（1 命中 1 未命中）→ 确认 stats 正确写入

### T4 · /api/backtest 路由 + schema
- Pydantic：
  - `BacktestCreate`：`{ model_config_id, date_from, date_to, initial_capital? }`
  - `BacktestSummary`：BacktestSession + 加 `by_score_band`, `by_league`, `equity_curve`
  - `BacktestList`：{ items, total }
  - `BacktestCompare`：{ a, b }（两个 summary）
- 路由（全部 `get_current_user`，无 admin 限制）：
  - `POST /api/backtest`（创建并运行，同步返回结果）
  - `GET  /api/backtest?limit=&offset=`
  - `GET  /api/backtest/{id}`
  - `GET  /api/backtest/compare?a=<id>&b=<id>`
- 测试：5-6 用例

### T5 · 前端 `/backtest` 基础页

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 历史赔率只剩最新一份，可能与真实开赛赔率偏差 | 计划中已接受，在文档和 UI 中标注"基于当前抓取的赔率快照" |
| 大区间同步计算超时 | MVP 限制 `date_to - date_from <= 90 天`；超时统一 500 并在响应 detail 提示 |
| Kelly 初始本金敏感度高 | 前端表单默认 10000，允许用户覆盖，结果区显示假设条件 |
