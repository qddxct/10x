## 本次 P8 要做的（H1 三项）

### 任务 T1 · TD-2：`ModelConfig.name` 唯一性

**目标**：同名克隆/新建直接 400；历史重名数据做一次清理（若存在则手工改名，可在 alembic upgrade 里去重加后缀）。

**改动**：
- `backend/app/models/model_config.py` 字段增加 `unique=True`
- `backend/alembic/versions/0007_model_config_name_unique.py`：
  - `upgrade()`：先扫描重名并批量改名为 `<name>_dup_<id>`，再加唯一索引 `uq_model_configs_name`
  - `downgrade()`：删索引即可
- `backend/app/services/model_config.py` 在 `create` / `clone` / `update` 时先 `db.query(ModelConfig).filter_by(name=...)` 预检，重名抛 `HTTPException(400, "model_config name already exists")`
- 前端 `ModelClient` 已用 `ApiError.detail` 展示后端错误，无需改动；测试补一个"克隆同名返回 400 + 前端错误横幅"用例

### 任务 T2 · TD-1：`/api/reviews` PATCH 乐观锁

**目标**：两个 admin 同时改一条 `MatchScore`，后写者必须收到 409，而不是静默覆盖。

**改动**：
- `backend/app/schemas/review.py`：`ReviewUpdate` 增加可选 `expected_updated_at: datetime | None`
- `backend/app/api/reviews.py`：
  - `PATCH /api/reviews/{score_id}`：如果客户端传了 `expected_updated_at`，执行 `UPDATE match_scores SET ... WHERE id=:id AND updated_at=:expected`，`rowcount==0` 时 `raise HTTPException(409, "review has been updated by someone else")`；未传则保留现有行为（向后兼容）
- 前端：
  - `lib/reviews/types.ts` 增加 `expected_updated_at` 到 payload
  - `app/review/review-client.tsx`：每次 PATCH 带上当前行的 `updated_at`；若收到 409，显示错误并强刷列表
- 测试：`backend/tests/test_api_reviews.py` 增加"两次 PATCH，第二次带旧 updated_at → 409"

### 任务 T3 · TD-6：激活模型自动重算今日评分

**目标**：admin `/activate v2` 后，当日 `match_scores` 自动改用 v2 计算；Dashboard 刷新即看到新分数。

**改动**：
- `backend/app/api/model_config.py`：`POST /api/model-configs/{id}/activate` 在 commit 之后调用 `ScoringService.compute_for_date(today_local(), cfg_id=new_id, force=True)`，返回值里多一个 `scores_recomputed: int` 字段
- `backend/app/schemas/model_config.py`：`ActivateResponse` 增加 `scores_recomputed`
- 前端：`lib/model-config/api.ts` 的 `activateModelConfig` 返回类型扩展；`ModelClient` activate 成功后 toast 提示重算数量
- 测试：`backend/tests/test_api_model_config.py` 增加"activate 会触发当日重算并返回 scores_recomputed 正确"

> 说明：**不**在这里做异步后台 job——当日待计算场次数量通常 < 50 条，同步 1~2s 可接受；后续若数据量爬到千级再上队列。
