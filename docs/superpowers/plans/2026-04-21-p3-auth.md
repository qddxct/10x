# P3 — 用户认证模块

**目标**：手机号 + 密码登录、JWT 鉴权、角色权限（admin / member）、前端登录页与路由守卫。基于已落地的 `users` 表（P2）。

**分支**：`feat/p3-auth`  
**前置依赖**：P1（脚手架）、P2（User 模型 & Alembic）

---

## 决策摘要

| 项 | 决策 |
| --- | --- |
| 密码哈希 | `passlib[bcrypt]`（bcrypt，cost=12） |
| JWT | `python-jose[cryptography]`，HS256，默认 30 天（`JWT_EXPIRE_MINUTES=43200`） |
| Token 载体 | Header: `Authorization: Bearer <token>`；前端存 `localStorage`（v1 简化，后续可升级 HttpOnly Cookie） |
| 角色 | `admin` / `member`（DB enum 已有） |
| 权限粒度 | `get_current_user`（登录即可） + `require_roles([...])` 依赖生成器 |
| 初始化 admin | seed 脚本自动创建默认 admin（可环境变量覆盖）+ 提供 CLI `python -m app.scripts.create_admin` |
| 前端范围 | 登录页 `/login` + middleware 路由守卫 + 顶部导航显示用户名/退出；**不做注册页**（admin 模块内管理用户 → 后续 admin 模块承担，P3 通过 `/api/users` 提供 admin-only 的新增/删除/改密接口） |
| 前端状态 | Zustand store `useAuthStore`：`{ token, user, login(), logout(), hydrate() }`；`nuqs` 不使用 |
| 未认证处理 | middleware 未检测到 token → 重定向 `/login?redirect=<path>`；后端 401 → 前端 `api` wrapper 清 token + 跳 `/login` |
| 不做 | 注册页 / 邮箱验证 / 短信验证码 / 刷新 token（v2 再做） |

## 验收标准

1. 启动 `docker compose up`，后端 `/api/auth/login` 用默认 admin 登录成功返回 JWT。
2. 前端访问 `/` 未登录 → 重定向 `/login`；登录后显示顶部用户名。
3. 以 member 身份调用 `GET /api/users` 返回 403；admin 返回 200。
4. `pytest -q`、`ruff`、`black`、`pnpm test`、`pnpm build` 全部绿。
5. CI（backend.yml + frontend.yml）全部绿。
