# V3.3 单场因子诊断与二串一可行性评估设计

日期: 2026-04-26
状态: Draft，等待人工确认后再写实现计划
负责人: Codex + 业务方共同校验

## 1. 背景

V3.2 已经得到一个可观察的候选模型 `empirical-v32-filtered-candidate`:

| 指标 | 值 |
| --- | ---: |
| 历史候选 | 561 场 |
| 普通平 | 514 场 |
| 让平 | 47 场 |
| 全量 ROI | +11.27% |
| 90 天窗口正 ROI | 7/7 |

但真实业务目标不是单场下注，而是给投注站提供可销售的高赔推荐。中国体彩体育竞猜常见约束是二串一，因此模型不能只看单场 ROI，还必须回答:

1. 是否有足够频次形成推荐。
2. 哪些单场因子真正提升平/让平质量。
3. 二串一组合是否比随机买更有优势。
4. 老板能否直观看到“模型不是碰运气”。

V3.3 不直接上线今日推荐，也不直接生成生产模型。它是一个研究工作台版本，用来把单场因子、组合能力、随机对照组统一放进报告和页面。

## 2. 目标

V3.3 回答四个问题:

```text
Q1: V3.2 的单场候选里，哪些因子真正影响平/让平命中和 ROI？
Q2: 如果按天或两天滚动组二串一，推荐频次能否满足业务要求？
Q3: 模型组相比随机买、约束随机买，优势是否显著？
Q4: 后续应该优化单场候选池，还是开始设计正式组单模型？
```

V3.3 的产出必须让业务方能看懂:

1. 模型组收益。
2. 随机组收益。
3. 模型超过随机多少百分位。
4. 每天/每两天能出单的覆盖率。
5. 最大连续不中和回撤风险。

## 3. 非目标

本版本不做以下事情:

1. 不接今日推荐。
2. 不激活任何新模型。
3. 不修改 V3.2 score 规则。
4. 不把组合结果当作生产投注建议。
5. 不为了提高回测收益做复杂参数搜索。

如果 V3.3 发现明显数据缺口，只记录数据源需求，不在本版本强行补齐。

## 4. 总体方案

采用“两层研究，不混成一团”的架构:

```text
历史比赛 + 赔率 + 状态特征
        │
        ▼
单场候选池分析层
        │  输出: 平/让平单场候选、因子分层、单场表现
        ▼
二串一组合模拟层
        │  输出: 同日/两日组单、组合赔率、命中、ROI、频次
        ▼
随机对照层
        │  输出: 随机分布、约束随机分布、模型百分位
        ▼
报告与页面展示层
```

原则:

1. 单场候选池和组单逻辑分离。
2. 模型组和随机组使用同一日期范围、同一盘口数据、同一投注口径。
3. 所有实验必须记录版本名、输入模型、数据范围、随机种子和生成时间。
4. 报告数据优先写入结构化表，Markdown/CSV 只是导出视图。

## 5. 输入数据

### 5.1 当前可用数据

V3.3 先使用现有数据库字段:

| 数据类别 | 表/来源 | 用途 |
| --- | --- | --- |
| 比赛列表 | `sporttery_matches` | 日期、联赛、主客队、开赛时间 |
| 赛果 | `sporttery_match_results` | 判断平/让平是否命中 |
| 赔率 | `sporttery_match_odds` | 平赔、让平赔、让球数、盘口过滤 |
| 球队状态 | `sporttery_match_team_stats` | 排名、近况、历史交锋派生因子 |
| 候选 score | `sporttery_match_scores` | V3.2 候选池 |
| 回测会话 | `backtest_sessions` | 页面展示现有回测结果 |

### 5.2 暂不新增但可能需要的数据

如果 V3.3 诊断发现解释力不足，再向业务方要数据源:

| 因子 | 价值 | 当前处理 |
| --- | --- | --- |
| 伤停/停赛 | 影响强弱和进球预期 | 先不接，列为数据缺口 |
| 赛程密度/轮换 | 影响冷门和平局 | 可由比赛日期部分派生，精细版后续补 |
| 临场赔率变化 | 判断市场异动 | 当前只有快照，后续需要历史赔率快照 |
| 联赛阶段/战意 | 保级/争冠/杯赛轮换 | 先用联赛和日期粗分，后续找数据源 |
| 天气/场地 | 影响低比分和平局 | 暂不接 |

只要需要新增数据源，Codex 必须先写明:

1. 需要什么字段。
2. 为什么现有数据不够。
3. 推荐抓取来源。
4. 是否存在历史泄漏风险。

## 6. 单场因子诊断

V3.3 先以 V3.2 候选池为基础，拆分普通平和让平。

### 6.1 普通平诊断维度

| 维度 | 示例分层 |
| --- | --- |
| 平赔区间 | 3.10-3.29、3.30-3.49、3.50+ |
| 让球绝对值 | 0、0.25、0.5、0.75+ |
| 联赛 | 英超、德甲、意甲、日职等 |
| 近期平局合计 | 低/中/高 |
| 近期低比分合计 | 低/中/高 |
| 历史交锋平局率 | 低/中/高 |
| 一球小胜/小负倾向 | 低/中/高 |
| 主客排名差 | 主强、均势、客强 |
| 近期进球差 | 主队强、均势、客队强 |

每个分层输出:

```text
bets, hits, hit_rate, avg_odds, roi, pnl, max_losing_streak
```

### 6.2 让平诊断维度

| 维度 | 示例分层 |
| --- | --- |
| 让球数 | +0.75、+1、+1.25、+1.5 等 |
| 让平赔区间 | 3.10-3.39、3.40-3.69、3.70+ |
| 强弱差 | 主强让球、客强受让、均势盘 |
| 近期小负倾向 | 低/中/高 |
| 交锋一球差倾向 | 低/中/高 |
| 联赛 | 按联赛拆分 |

让平样本只有 47 场，所有结论必须标注样本量风险。任何小于 30 场的分层只作为观察，不作为规则收敛依据。

## 7. 二串一组合模拟

### 7.1 组合候选来源

默认只使用 V3.2 单场候选:

```text
model_config = empirical-v32-filtered-candidate
is_recommended = true
bet_type in ('draw', 'handicap_draw')
```

组合不改变单场命中定义:

```text
二串一命中 = 两场单场都命中
组合赔率 = odds_a * odds_b
固定投注盈亏 = 命中 ? stake * combo_odds - stake : -stake
```

### 7.2 组单策略

V3.3 至少模拟三种策略:

| 策略 | 说明 | 业务意义 |
| --- | --- | --- |
| 同日最强二串一 | 每个比赛日从候选中选 2 场 | 最接近日常推荐 |
| 两日滚动最强二串一 | 今天不够 2 场时允许跨今天+明天 | 提高频次 |
| 高赔吸引二串一 | 在质量合格前提下优先提高组合赔率 | 更符合投注站引流 |

“最强”的初始排序不做复杂机器学习，先用可解释规则:

```text
让平候选优先级略高于普通平
total_score 高优先
赔率处于有效区间优先
同联赛/同球队风险相关性不额外加分
```

后续如果需要正式组单模型，再独立设计 V3.4。

### 7.3 组合类型拆分

必须分别统计:

1. 平 + 平。
2. 平 + 让平。
3. 让平 + 让平。

输出指标:

```text
combo_count, hit_count, hit_rate, avg_combo_odds, median_combo_odds,
roi, pnl, active_days, coverage_rate, max_losing_streak
```

## 8. 随机对照组

随机对照是 V3.3 的硬性要求。没有随机对照，报告无效。

### 8.1 随机组 A: 全市场随机买

在同一日期范围内，从所有有结果和赔率的竞彩比赛中随机选择平/让平。

用途:

```text
证明模型不是比“纯瞎买”略好，而是有实际筛选能力。
```

### 8.2 随机组 B: 约束随机买

约束随机组必须尽量公平，遵守和模型组相同的业务约束:

1. 同一日期范围。
2. 同一投注类型集合: 平/让平。
3. 同样组二串一。
4. 同样每日或两日滚动频率。
5. 尽量匹配赔率区间。
6. 尽量匹配每个窗口的下注数量。

用途:

```text
证明模型不是因为“只买高赔”或“只挑有比赛多的日期”而占便宜。
```

### 8.3 随机次数和种子

默认参数:

```text
random_trials = 1000
random_seed = 20260426
```

报告必须输出:

1. 随机平均 ROI。
2. 随机 ROI 中位数。
3. 随机 80/90/95 分位 ROI。
4. 模型 ROI 位于随机分布的百分位。
5. 模型最大连续不中与随机分布对比。

## 9. 报告与页面设计

### 9.1 Markdown 报告

生成:

```text
docs/analysis/2026-04-26-v33-single-factor-and-combo-diagnostic.md
```

Markdown 至少包含:

4. 普通平/让平拆分。
5. 二串一策略对比。
6. 随机对照分布。
7. 业务频次指标。

### 9.2 页面展示

V3.3 建议新增“研究报告”视图，而不是继续把所有内容塞进历史回测列表。

页面可以分两步实现:

第一步:

1. 回测页面列表能看到“研究报告”入口。
2. 点击后展示摘要指标和 Markdown/结构化结果。

第二步:

1. 新增 `/research` 或 `/model-lab` 页面。
2. 支持按实验版本查看因子分层、组合模拟、随机分布。

本版本如果时间有限，优先完成第一步，避免前端过早复杂化。

## 10. 建议表结构

V3.3 可以先用文件报告，但为了避免文档和页面脱节，推荐新增结构化研究表。

### 10.1 model_research_runs

保存一次研究实验的元信息:

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| name | 实验名，如 `v33-single-factor-combo-diagnostic` |
| base_model_config_id | 输入模型，如 V3.2 的 id=8 |
| date_from/date_to | 数据范围 |
| random_seed | 随机种子 |
| random_trials | 随机次数 |
| status | running/succeeded/failed |
| summary_json | 摘要指标 |
| report_path | Markdown 报告路径 |
| created_at/updated_at | 时间戳 |

### 10.2 model_research_artifacts

保存因子分层、组合模拟、随机对照结果:

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| run_id | 关联研究 run |
| artifact_type | factor_bucket/combo_simulation/random_baseline/window_summary |
| label | 分组名 |
| payload_json | 结构化结果 |
| created_at | 时间戳 |

设计理由:

1. 避免继续滥用 `backtest_sessions` 存研究报告。
2. 保持页面可查询，不依赖解析 Markdown。
3. 每次实验可追溯，文档不容易腐败。
4. 后续 V3.4 组单模型可以复用研究 run。

## 11. 文档新鲜度机制

为了避免文档腐败，从 V3.3 开始引入模型研究索引:

```text
docs/analysis/MODEL_RESEARCH_INDEX.md
```

每次新增或修改模型实验，必须同步更新索引中的:

1. 最新候选模型。
2. 是否激活。
3. 输入数据范围。
4. score 数量。
5. 回测/研究报告路径。
6. 页面是否可见。
7. 下一步状态。

文档规则:

1. 所有新文档使用中文。
2. 旧文档如果是历史快照，不直接改结论，只在索引里标注“历史版本”。
3. 实现与设计发生偏差时，必须先更新当前设计文档的“偏差记录”再继续写代码。
4. 报告中的数据必须来自脚本输出或数据库查询，不能手填猜测。
5. 页面字段变更必须同步写入相关设计文档或索引。

V3.3 实现时禁止把所有逻辑堆进一个巨大脚本。建议拆分:


测试要求:

1. 因子分层统计单测。
2. 二串一命中和赔率计算单测。
3. 随机种子可复现单测。
4. 随机约束数量匹配单测。
5. 报告摘要字段完整性单测。

## 13. 验收标准

文档验收:

1. 本文档经人工确认。
2. `MODEL_RESEARCH_INDEX.md` 已同步记录 V3.3 状态。
3. 文档均为中文。
4. 明确写出随机对照组。
5. 明确写出数据源缺口处理方式。

功能验收:

1. 生成 V3.3 Markdown 报告和 CSV。
2. 至少输出普通平/让平各自的因子分层。
3. 至少输出三种二串一策略表现。
4. 至少输出随机组 A 和约束随机组 B。
5. 模型 ROI 百分位可见。
6. 页面能看到研究摘要或报告入口。

质量验收:

1. 单元测试通过。
2. ruff 通过。
3. 新增代码模块边界清楚。
4. 不影响 active 模型。
5. 不改变今日推荐。
6. 不删除 V3.1/V3.2 研究结果。

## 14. 当前建议

V3.3 先不寻找新数据源，先用现有 2024-09-28 至 2026-04-22 的历史数据完成诊断。

如果报告发现以下情况，再向业务方要数据源:

1. 某些联赛表现极端但无法解释。
2. 临场赔率变化可能解释大部分误差。
3. 强队让球平命中与伤停/轮换强相关。
4. 两日滚动组合频次仍不足，需要扩大候选池。

当前推荐路线:

```text
先优化单场候选质量，同时用二串一模拟约束单场优化方向。
不要现在直接做纯组合模型。
```
