# 历史抓取旁路审计设计

## 背景

我们已经修正了数据源边界：未来推荐需要 Sporttery 赛程与官方赔率、Titan007 欧赔与 analysis 状态；历史回填的球队状态只能来自 Titan007 `analysis/{match_id}cn.htm`。下一步需要用新代码抓取一段历史数据，和现有正式表做对比，确认是否存在数据质量问题。

## 目标

1. 新建比赛相关的旁路审计表，不覆盖正式数据。
2. 使用新抓取链路抓取一个月历史数据。
3. 将新抓结果与正式表逐字段对比，输出差异明细。
4. 生成中文 Markdown 数据质量报告，用于决定是否需要重抓正式历史数据。

## 非目标

1. 本次不直接修正式表数据。
2. 本次不重新训练模型。
3. 本次不把审计数据接入今日推荐或回测页面。

## 审计表设计

新增三张表，由审计脚本按需创建：

| 表 | 用途 |
|---|---|
| `data_audit_runs` | 每次审计任务的元信息、日期范围、统计摘要 |
| `data_audit_match_snapshots` | 新抓取链路得到的比赛、赛果、赔率、球队状态快照 |
| `data_audit_diffs` | 新抓快照与正式表的字段级差异 |

这些表属于临时审计资产，可以后续删除，不进入模型主流程。

## 新抓链路

对每个业务日期执行：

1. Sporttery `getUniformMatchResultV1.qry`：官方比赛、赛果、HAD、HHAD 让球数。
2. Titan007 `JcResult.aspx`：竞彩编号到 Titan007 match id 的映射。
3. Titan007 `oddsData.aspx?cid=1&st=1`：历史澳门欧赔和亚盘。
4. Titan007 `analysis/{match_id}cn.htm`：历史球队状态、近况、交锋。

抓取结果只写入 `data_audit_match_snapshots`。

## 对比范围

| 分类 | 字段 |
|---|---|
| 比赛基础 | 逻辑 ID、竞彩编号、联赛、主队、客队、开赛日期 |
| 赛果 | 主队进球、客队进球、胜平负、让球胜平负 |
| 竞彩赔率 | HAD 胜平负、HHAD 让球数、HHAD 胜平负 |
| Titan007 赔率 | 欧赔胜平负、亚盘让球、亚盘主客赔率 |
| 球队状态 | 排名、赛季胜平负、近期 form、近期进失球、交锋平局/一球差/大小球倾向 |

差异按严重程度分为：

| 严重程度 | 含义 |
|---|---|
| `missing_existing` | 正式表缺失，新抓有值 |
| `missing_audit` | 正式表有值，新抓缺失 |
| `mismatch` | 两边都有值但不同 |

## 验收标准

1. 审计脚本可以创建审计表并完成一个月抓取。
2. 报告包含抓取场次、正式表覆盖率、差异数量、主要差异字段 Top 列表。
3. 正式表没有被写入或覆盖。
4. 脚本支持 `--dry-run-days` 或短日期范围，便于小范围验证。
