# V3.4 二串一组单选择器设计

日期: 2026-04-26
状态: Draft，等待人工确认后实施

## 1. 背景

V3.3 已经把 V3.2 单场候选池放进二串一场景，并加入随机对照。

关键结果:

| 指标 | 值 |
| --- | ---: |
| V3.2 候选场次 | 561 |
| 同日最强二串一 | 132 单，ROI +17.04% |
| 两日滚动最强二串一 | 144 单，ROI +17.89% |
| 高赔吸引二串一 | 132 单，ROI -3.24% |
| 全市场随机 ROI 均值 | -20.30% |
| 模型超过全市场随机分位 | 90.3% |
| 约束随机 ROI 均值 | +24.13% |
| 模型超过约束随机分位 | 42.0% |

这说明:

1. V3.2 单场候选池明显优于全市场随机。
2. 但当前“按分数选最强两场”的组单方式没有跑赢候选池内约束随机。
3. 单场候选池里可能存在更多有效组合，问题在组单选择器。
4. 高赔优先会伤害命中质量，不能把“高赔率吸引客户”理解成盲目拉高赔率。

V3.4 的目标是只优化组单选择器，不修改 V3.2 单场候选规则。

## 2. 目标

V3.4 回答一个问题:

```text
在 V3.2 候选池不变的前提下，能否找到一个可解释、可回测、能跑赢约束随机的二串一组单选择器？
```

核心指标:

1. ROI 高于约束随机均值。
2. 模型 ROI 至少超过约束随机 60% 分位，理想目标 70% 分位。
3. 推荐频次不低于 V3.3 两日滚动策略的 80%。
4. 最大连续不中低于或接近约束随机均值。
5. 组合赔率仍具备客户感知吸引力，平均组合赔率不低于 9.0。

## 3. 非目标

本版本不做:

1. 不修改 V3.2 单场候选规则。
2. 不新增今日推荐。
3. 不接生产模型。
4. 不用复杂机器学习模型。
5. 不新增外部数据源。

V3.4 是组单研究，不是生产推荐。

## 4. 设计思路

V3.4 不再只用 `total_score` 排序，而是引入“组合适配度”。

组单质量来自三部分:

```text
单腿质量 + 两腿互补 + 组合风险控制
```

### 4.1 单腿质量

单腿质量不是越高分越好，而是看历史诊断里更稳的区域。

初始特征:

| 特征 | 方向 |
| --- | --- |
| bet_type | 让平可小幅加分，但不能过度，因为样本少 |
| odds | 赔率过低吸引力不足，过高命中风险上升 |
| total_score | 保留基础质量排序 |
| league bucket | 已验证为正的联赛加分，负 ROI 联赛降权 |
| bet_type + odds range | 平/让平各自赔率区间表现不同 |
| sample_note | 小样本只观察，不强加分 |

### 4.2 两腿互补

二串一不是挑两个最高分即可。要降低同质风险。

组合惩罚:

1. 同联赛组合降权。
2. 两场都是高赔率边缘候选降权。
3. 两场都是同一 bet_type 时轻微降权，尤其 `draw+draw`。
4. 两场都来自历史负 ROI 分层时强降权。

组合加分:

1. 一场普通平 + 一场让平，若让平质量合格。
2. 两场来自不同联赛。
3. 两场赔率组合在 9.0 到 14.0 的可售卖区间。
4. 两场都来自非负 ROI 分层。

### 4.3 组合赔率控制

客户需要“高赔感”，但 V3.3 已证明盲目高赔会亏。

V3.4 初始目标区间:

```text
9.0 <= combo_odds <= 14.0
```

原因:

1. 平/让平单腿赔率通常 3.1 到 3.8。
2. 二串一组合赔率自然落在 9.6 到 14.4。
3. 过高组合赔率通常来自两个高风险腿叠加。

## 5. 候选策略

V3.4 同时回测三种新策略，与 V3.3 策略对照。

### 5.1 balanced_selector

平衡型，推荐作为默认候选。

排序逻辑:

```text
pair_score = leg_score_a + leg_score_b + complement_bonus - risk_penalty
```

约束:

1. 同日优先。
2. 同日不足或无合格组合时，两日滚动。
3. 组合赔率必须在 9.0 到 14.0。
4. 同联赛不禁止，但扣分。

### 5.2 conservative_selector

稳健型，用于减少连续不中。

约束更严:

1. 排除 V3.3 因子报告中的明显负 ROI 联赛。
2. 组合赔率在 9.0 到 12.8。
3. 至少一条腿来自可参考样本的非负 ROI 分层。
4. 允许频次下降。

### 5.3 frequency_selector

频次型，用于投注站日常运营。

约束更宽:

1. 两日滚动。
2. 组合赔率在 8.5 到 15.0。
3. 候选不足时允许同类型组合。
4. 目标是提高覆盖天数，但必须和随机对照比较。

## 6. 随机对照

V3.4 必须沿用 V3.3 随机对照，并新增“同频约束随机”。

对照组:

| 对照 | 说明 |
| --- | --- |
| 全市场随机 | 从全部竞彩平/让平里随机组二串一 |
| 候选池约束随机 | 从 V3.2 候选池随机组二串一 |
| 同频约束随机 | 与某个策略生成相同单数、相近日期覆盖、相近赔率区间 |

报告必须展示:

1. 策略 ROI。
2. 随机均值 ROI。
3. 随机 80/90/95 分位。
4. 策略超过随机的百分位。
5. 最大连续不中对比。

## 8. 验收标准

功能验收:

1. 生成三种 V3.4 组单策略。
2. 每种策略都有随机对照百分位。
3. 报告写入 DB、Markdown、CSV。
4. 页面显示最新研究 run。

效果验收:

1. 至少一种策略 ROI 高于 V3.3 同日最强 `+17.04%`。
2. 至少一种策略超过候选池约束随机 60% 分位。
3. 至少一种策略平均组合赔率不低于 9.0。
4. 若全部失败，也必须如实报告失败原因。

质量验收:

1. 不修改 V3.2 score。
2. 不影响 active 模型。
3. 单测通过。
4. ruff 通过。
5. 文档索引同步更新。

## 9. 当前判断

V3.4 的关键不是“更高赔率”，而是“在候选池里找更好的两场搭配”。

如果 V3.4 跑不赢约束随机，说明当前候选池里的有效信号主要来自单场筛选，组单排序还缺少关键因子。那时再考虑补充临场赔率变化、伤停、战意等数据源。
