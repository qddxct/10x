# Titan007 欧赔兜底设计

## 背景

2026 年 3 月旁路审计发现 8 场比赛没有澳门欧赔。经业务确认，这些比赛不是抓取错误，而是澳门没有开欧赔。为了减少历史数据和未来评分中的赔率缺口，需要增加兜底欧赔来源。

实测结果：

1. Titan007 日期接口 `oddsData.aspx?cid=1` 可稳定返回澳门欧赔，是主来源。
2. 此前备选的其他公司日期接口对历史日期不稳定，不作为兜底实现。
3. 单场欧赔明细 JS `https://1x2d.titan007.com/{match_id}.js` 可返回多家公司欧赔。
4. 香港马场在单场 JS 中公司 ID 为 `432`，英文名 `HK Jockey Club`，中文标识 `香港马*(中国香港)`。

## 目标

1. 历史抓取优先使用澳门 `oddsData.aspx?cid=1`。
2. 如果某场比赛澳门没有欧赔，则从单场欧赔 JS 中读取香港马场 `company_id=432` 的当前欧赔补齐。
3. 不覆盖已有澳门赔率；只有缺失 match id 才使用香港马场兜底。
4. 旁路审计脚本继续复用同一套 `fetch_titan_day()` 逻辑，不单独分叉。
5. 本次只保留香港马场兜底逻辑，避免不可用备选接口造成抓取失败或噪声日志。

## 非目标

1. 本次不改正式表结构，不新增 bookmaker 字段。
2. 本次不补亚盘兜底；香港马场单场欧赔 JS 只用于补欧赔，亚盘字段保持为空。
3. 本次不改未来实时赔率 feed；若未来推荐缺欧赔，再单独接入未来赛程兜底。
4. 本次不重跑全部历史数据，只先验证 2026 年 3 月缺口是否可补。

## 数据格式

单场 JS 示例：

```text
var game=Array("432|...|HK Jockey Club|初主|初平|初客|...|当前主|当前平|当前客|...|香港马*(中国香港)|...");
```

字段规则：

| 字段下标 | 含义 | 写入字段 |
|---:|---|---|
| 0 | 公司 ID | 必须等于 `432` |
| 10 | 当前主胜欧赔 | `win_odds` |
| 11 | 当前平局欧赔 | `draw_odds` |
| 12 | 当前客胜欧赔 | `lose_odds` |

## 方案

1. `history.py` 保留澳门日期接口解析器 `parse_odds_data()`。
2. `history.py` 新增 `parse_oddslist_js_company()`，按公司 ID 从单场 JS 中提取当前欧赔。
3. `backfill.py` 的 `fetch_titan_day()` 先抓 `JcResult.aspx` 拿到当日比赛列表，再抓澳门日期欧赔。
4. `fetch_titan_odds_with_fallback(client, target_date, matches)` 找出澳门缺失的 match id，只对缺失比赛请求 `https://1x2d.titan007.com/{match_id}.js`。
5. 香港马场兜底结果与澳门结果按优先级合并：澳门优先，香港马场只补缺口。

## 验收标准

1. 单元测试证明：同一 match id 澳门和香港马场都存在时保留澳门。
2. 单元测试证明：澳门缺某 match id 时使用香港马场补齐。
3. 单元测试证明：`parse_oddslist_js_company()` 能从单场 JS 中提取香港马场当前欧赔。
4. 重新跑 2026 年 3 月审计后，Titan007 欧赔覆盖从 `162/170` 提升到更高；如果香港马场对这 8 场均有开盘，应达到 `170/170`。
